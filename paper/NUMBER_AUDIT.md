# Number audit: paper/ quantitative claims

Every quantitative value cited in `paper/sections/*.tex` is a `\NumXXX`
LaTeX macro, never a hand-typed literal (enforced by
`scripts/check_doc_citations.py`'s `find_hand_typed_numbers` check, part
of the citation gate). This document maps each macro actually cited in
the paper's prose back to the script and file that generates it, plus
the value it held at the time of the most recent `make paper.pdf` build.
Re-run `python scripts/build_paper_values.py` (or `make -C paper values`)
after any upstream `analysis/*.csv` changes; this table will then be
stale until regenerated by hand alongside it, since it is a document,
not a build artifact.

All macros are defined in `paper/values.tex`, generated by
`scripts/build_paper_values.py` from `analysis/*.csv` files, which are
themselves generated by the scripts named below (see each CSV's own
provenance doc, e.g. `analysis/COMPARISON_PROVENANCE.md`, for the full
chain back to raw results).

## Design constants (not pipeline-derived)

Three macros are fixed, pre-registered values rather than statistics computed
from `analysis/*.csv`. They are hardcoded in `build_paper_values.py` (not read
from a file) because their authoritative source is prose in a pre-registration
document, not tabular data:

- `\HFiveTauThreshold` (0.7) — `docs/Approved_Hypotheses.md:16`, H5's approved wording.
- `\HSixBandLow` / `\HSixBandHigh` (0.4 / 0.8) — `analysis/RQ5_ANALYSIS_PLAN.md:91`,
  the pre-registered validity-supporting band.
- `\SigLevel` (0.05) — the standard statistical significance convention, not
  specific to this project; included as a macro (rather than a suppressed
  literal) only because it sits mid-paragraph in `04_results.tex`, where a
  same-line suppression comment would silently drop the rest of that
  paragraph from the compiled PDF (see commit `0670a4a`).

sample is complete; re-running `compute_validated_score.py` then
`build_paper_values.py` will populate the macros automatically.

## Numbers exempted from macro form (`% cite:external`)

Five lines in `paper/sections/{03_methods,04_results}.tex` carry a
`% cite:external` end-of-line marker suppressing the hand-typed-number
lint, because the flagged digits are model name/version/parameter-count
identifiers (e.g. the "1.5" in "Qwen2.5-Coder-1.5B-Instruct", the "3.1" in
"Gemini 3.1 Pro Preview") rather than pipeline-derived results — there is
no `analysis/*.csv` row these could be sourced from, since they are the
model's own published name, not a measurement:

- `03_methods.tex:16` — "1.5"/"3.1"/"2.5" (Qwen2.5-Coder, Gemini 3.1, Gemini 2.5)
- `03_methods.tex:19` — "1.5" (Qwen2.5-Coder-1.5B-Instruct)
- `04_results.tex:8` — "1.5" (Qwen2.5-Coder-1.5B-Instruct)
- `04_results.tex:20` — "1.5" (Qwen2.5-Coder-1.5B-Instruct)
- `04_results.tex:56` — "3.1" (Gemini 3.1 Pro Preview)

Each marker must be the last token on its physical source line — see the
CAUTION note in `scripts/check_doc_citations.py`'s module docstring for
why a mid-paragraph placement is unsafe in this codebase (paragraphs are
written as single physical lines; `%` comments to true end-of-line).

## Verification

- This document is itself registered in `check_doc_citations.py`'s
  `DOC_FILES` (`paper_number_audit`), but its own tables produce zero
  extractable claims from the checker's pipe-table parser: that parser
  tags an entire *column* by one statistic kind via its header (e.g. a
  column literally named `kendall_tau` or `p_value`), and this table's
  `Value` column deliberately mixes every kind (τ, p-values, percentage
  points, counts) across rows, by design, to stay one readable table
  rather than eleven single-kind ones. A checker run against this file
  alone therefore reports `0 match, 0 mismatch` and a vacuous `GATE:
  PASS` — not evidence of correctness on its own (the zero-items-checked
  failure mode this project has hit before, e.g. the `validate.py`
  stale-path bug and `archive_diversity_audit.py`'s hardcoded summary).
  The real check performed here was a direct, scripted diff of every
  `Value` cell against `paper/values.tex`'s own `\newcommand` definitions
  (43 macro references, 0 mismatches) — stronger for this specific
  purpose (exact-string equality against the single generating file)
  than the checker's own tolerance-banded reference-corpus lookup would
  be, and re-runnable the same way after any future edit to this table.
- Every macro used in `paper/sections/*.tex` and `paper/paper.tex` resolves
  to a `\newcommand` in `paper/values.tex` (checked by compiling; zero
  "Undefined control sequence" errors in `paper.log`).
- Citation gate (`scripts/check_doc_citations.py`): 414 match, 0 mismatch,
  0 hand-typed, GATE: PASS, run against the full repository including
  `paper/values.tex` and every `paper/sections/*.tex` file.
- All 18 references in `paper/references.yaml` are cited exactly once in
  the prose (`\cite{}`); zero unused entries, zero unresolved keys
  (checked by diffing `\cite{}` keys used against `references.yaml`'s
  own key list, and confirmed independently by zero warnings in
  `paper.blg` and zero "Citation ... undefined" lines in `paper.log`).
- Compiled PDF (`make -C paper paper.pdf`) is 8 pages, matching the
  strict page limit; `pdftotext`-extracted text confirmed complete
  against source for every subsection, including all six hypotheses'
  verdict sentences (H2 supported; H1 Test 1 not supported; H1 Test 2
  mixed; H3 supported as a monotone trend; H5's threshold not met; H6
  clause 1 mixed, clause 2 not supported) — this check exists because an
  earlier draft of the `% cite:external` marker mechanism silently
  dropped H5's verdict sentence from the compiled PDF without any
  compiler or gate error (see commit `0670a4a`); a source-only review
  would not have caught it.
