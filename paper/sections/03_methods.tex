\section{Methods}
\label{sec:methods}

\subsection{Template Grammar and Complexity Tiers}
The dynamic benchmark is built from sixty hand-authored templates, each specifying a body skeleton with parameter placeholders, a parameter-domain specification, a reference oracle implementation, and a docstring template with synonym variation. A \emph{benchmark instantiation} is one full generator run: every template sampled once per seed to produce, in this study's design, fifteen templates per tier across four tiers with five instances per template, for 300 problems per instantiation. Templates are stratified across four cyclomatic-complexity (CC) tiers -- L1 (Trivial, CC 1, single-path pure transformations), L2 (Branching, CC 2--3, disjoint conditional logic), L3 (Iterative, CC 4--7, one or two loops with boundary conditions), and L4 (Compositional, CC ${\geq}8$, nested branches and loops with multiple failure modes) -- with target mutant-count bands of 5--10, 10--15, 15--25, and 25--40 respectively. Cyclomatic complexity is computed statically at template-validation time and recomputed on every generated instance to confirm continued tier membership, since parameter sampling can in principle shift a generated instance's control-flow shape. Prior to use, the full sixty-template corpus passed a within-tier diversity check (zero of sixty templates flagged for near-duplicate structure) and a tier-separation sanity check, both required by the study's own pre-registered corpus-validation gate.

\subsection{Seeded Instantiation and Oracle-by-Construction Scoring}
Each template yields fresh problem instances by sampling its parameter domain -- variable names, literal values, constants, and docstring phrasing all vary across instances -- under a deterministic seed, so a given (template, seed) pair reproduces identically across runs while distinct seeds produce distinct, previously unseen problem content. This is the property that distinguishes the benchmark from a static release: its problem space is defined by the template grammar and parameter domains, not by a fixed, publishable set of instances, so no single generated instantiation can itself be memorised by a future model in the way a static benchmark's exact published content can. Correctness is oracle-by-construction: every generated instance carries its own reference implementation, generated alongside it from the same template, so scoring never depends on a separately curated expected-output set that could itself drift out of sync with the generated problem.

\subsection{Mutation Operators and Metrics}
Test quality is scored by mutation testing using seven semantic-altering-change (SAC) operators: Arithmetic Operator Replacement, Relational Operator Replacement, Logical Operator Replacement, Constant Replacement, Boundary Mutation, Statement Deletion, and Return/Statement Mutation, applied as single-edit mutants. Semantic-preserving-change operators are out of scope for this study (Section~\ref{sec:conclusion}). Four metrics are recorded per problem: \emph{Exec@K}, whether the generated suite imports and is collected by the test runner without error (a gate, not a quality measure); \emph{baseline\_pass\_rate}, whether the suite passes against the original, correct implementation (the precondition for mutation scoring); \emph{Mut@K}, the fraction of mutants killed; and \emph{coverage\_adjusted}, Mut@K multiplied by baseline\_pass\_rate. Naming follows Pass@K convention, where $K$ denotes attempts per problem; every result in this study uses $K=1$. This is a distinct quantity from $m$, the number of sampled instances per template (Section~\ref{sec:methods}.A) -- the two are never interchangeable, and this dissertation's own working documents record having conflated the two symbols in an earlier draft before separating them permanently. $N$ denotes a third, unrelated quantity: the number of independent benchmark instantiations (full regenerations under a fresh seed) an analysis draws on, used only in the stability evaluation (H5, Section~\ref{sec:results}).

Mut@K is \emph{conditional}: its mean is taken only over problems whose generated suite already passes the baseline-correctness gate, excluding non-passing problems from the average entirely rather than scoring them zero. This is the pre-registered primary metric throughout this study. \texttt{coverage\_adjusted} is a zero-filled, unconditional reading of the same underlying data, algebraically identical to averaging Mut@K over every attempted problem with non-passing suites scored zero, and is reported throughout as a labelled co-primary rather than a replacement, since the two readings are different estimands that can disagree substantially for a model with a low baseline-pass rate.

\subsection{Models}
Nine models spanning four providers are evaluated: two closed-source frontier/efficient pairs from OpenAI and from Anthropic, one closed-source frontier/efficient pair from Google, and a three-point open-source scaling sweep (Qwen2.5-Coder, 32B/7B/1.5B parameters). The Google pair (Gemini 3.1 Pro Preview/Flash-Lite) is a forced substitution for the originally specified Gemini 2.5 Pro/Flash, which returned model-unavailable errors ahead of their provider's own stated retirement schedule; the substituted models preserve the same frontier-versus-efficient generational contrast. The OpenAI pair actually evaluated (\texttt{gpt-5-2025-08-07}/\texttt{gpt-5-mini-2025-08-07}) likewise differs from the version originally specified in this study's pre-registration; both substitutions are disclosed here rather than left implicit, since neither reflects a change in experimental design. Every model call is logged with model identifier, snapshot or revision, decoding parameters, seed, and timestamp; fine-tuned checkpoints are treated as a distinct model identity from their base weights, since adapter identity (Section~\ref{sec:methods}.E) changes what is being measured even when the base model field is unchanged. % cite:external -- "1.5"/"3.1"/"2.5" are model name/version/parameter-count identifiers (Qwen2.5-Coder, Gemini 3.1, Gemini 2.5), not result values

\subsection{Fine-Tuning Setup (Causal Contamination Probe)}
To isolate contamination-driven score inflation causally rather than observationally, the smallest open-source model (Qwen2.5-Coder-1.5B-Instruct) is fine-tuned via low-rank adaptation (LoRA)~\cite{hu2022lora} directly on ULT's own ground-truth test suites, restricted to the subset of ULT problems for which a repair-verified training pair could be constructed (112 of the 400-problem evaluation subsample; the remaining 288 problems, structurally unrepairable by the same verification pipeline, form a held-out unseen-ULT population). The fine-tuned checkpoint is then re-evaluated on ULT, on PLT, and on a fresh dynamic-benchmark instantiation, using a $2{\times}3$ difference-in-differences design (pre/post fine-tuning $\times$ \{ULT, PLT, dynamic\}) with bootstrap confidence intervals rather than a significance test, following this study's general preference for effect sizes with intervals over point-estimate hypothesis tests where an estimator naturally supports one. A dynamic-benchmark control population restricted to the two lower complexity tiers (L1--L3, outside ULT/PLT's own complexity floor) separates any generic fine-tuning improvement from contamination-specific inflation. % cite:external -- "1.5" is the model's own parameter-count identifier (Qwen2.5-Coder-1.5B-Instruct), not a result value

\subsection{Equivalent-Mutant Validation}
The mutation operators applied here can, as with any mutation-testing scheme, generate mutants that are semantically equivalent to the original program and therefore unkillable by any correct test suite, which would depress the raw mutation score without reflecting a genuine test-quality gap. The default reported score throughout this study is the raw, unadjusted mutation score, treated as a deliberately pessimistic and directly comparable headline figure. A validated companion score is separately obtained via manual inspection of a stratified sample of 120 mutants (thirty per complexity tier), from which an estimated equivalent-mutant rate with confidence intervals is derived and applied as a correction to the sampled population.
