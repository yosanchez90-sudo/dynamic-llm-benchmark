\section{Related Work}
\label{sec:related-work}

\textbf{Contamination evidence.} Sainz~\emph{et al.}~\cite{sainz2023contamination} argue that benchmark contamination measurement should be standard practice, it should not be assumed away, and Balloccu~\emph{et al.}~\cite{balloccu2024leakcheat} supports the concern empirically, tracing leaked benchmark references into closed-source model cards. The memorisation mechanism says: LLMs reproduce training sequences at rates that grow with model scale and with how often a sequence is duplicated in the training corpus~\cite{carlini2023quantifying}. Dong~\emph{et al.}~\cite{dong2026generalization} extend this line to code generation, distinguishing genuine generalisation from memorisation in code-LLM evaluation. These studies establish that contamination is real and detectable after training has happened; they do not offer an evaluation protocol that prevents it at measurement time, which is the gap the present work addresses for test generation.

\textbf{Dynamic evaluation.} A growing line of work responds to static-benchmark contamination by generating evaluation instances at test time rather than drawing from a fixed set. DyVal~\cite{zhu2024dyval} constructs reasoning problems from dynamic graphs; LiveBench~\cite{white2025livebench} refreshes its problem monthly against continuously updated sources; BeyondBench~\cite{srivastava2026beyondbench} generates algorithmic problems with mathematical correctness guarantees; MATHEMAGIC~\cite{obrien2025mathemagic} applies the same generative principle to mathematics benchmarks; and LLM-as-an-Interviewer~\cite{kim2025interviewer} replaces static test sets with a dialogue-driven evaluation. Each demonstrates that generative evaluation is practical at scale and resists the specific contamination failure mode static benchmarks exhibit. None targets unit-test generation, where the object being evaluated is itself executable code accompanied by a correctness oracle, where a generated test can be assessed by execution rather than by comparison to a reference string.

\textbf{Dynamic and contamination-aware benchmarking for code.} Closer to the present setting, DyCodeEval~\cite{chen2025dycodeeval} and the benchmark-usefulness study of Guan~\emph{et al.}~\cite{guan2025benchmarkuseful} both apply dynamic regeneration to code-reasoning benchmarks, and Code2Bench~\cite{zhang2025code2bench} scales dynamic benchmark construction directly from source repositories. LiveCodeBench~\cite{jain2025livecodebench} applies the same strategy, drawing its problems from programming contests held after model training cutoffs. Automated unit-test generation predates LLMs: search-based tools such as EvoSuite~\cite{fraser2011evosuite} and Pynguin~\cite{lukasczyk2022pynguin} synthesise test suites by evolutionary search, and recent empirical studies evaluate LLMs on the same task directly~\cite{schafer2024empirical, siddiq2024junit}. TestEval~\cite{wang2024testeval} and the software-evolution study of Haroon~\emph{et al.}~\cite{haroon2026evolution} evaluate LLM test generation, the latter tracking test quality as the codebase under test changes over time; MuCoCo~\cite{chou2026mucoco} evaluates code-LLM consistency via automated mutation-style perturbation, a close methodological parallel to the mutation-testing scoring used here. The static comparator adopted in this work, UnLeakedTestBench (ULT)~\cite{huang2026ult}, is a response to contamination: its authors decontaminate a corpus of real-world functions and construct PLT, a deliberately leaked twin, so that any contamination-consistent score gap between the two becomes directly observable, an experimental design this work reuses as one of its own contamination-evidence comparisons. Codex/HumanEval~\cite{chen2021codex} established code-generation benchmarking as a discipline but is reported as contaminated in later models. BigCodeBench~\cite{zhuo2025bigcodebench} serves in this work as an external, independently maintained code-generation proxy against which DyMuT's construct validity is checked.

\textbf{The gap.} No prior dynamic-benchmarking study combines template-based, seeded regeneration with a mutation-testing oracle for unit-test generation specifically, and none pairs an observational contamination comparison (dynamic versus a decontaminated static benchmark and its leaked twin) with a causal one (direct fine-tuning on the static benchmark's own ground truth, isolating contamination-driven inflation from generic capability gain). This work supplies both, together with a construct-validity check against an external, non-test-generation proxy, to establish not only that DyMuT resists contamination but that it continues to measure a capability that an independent evaluation recognises.
