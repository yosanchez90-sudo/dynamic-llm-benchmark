\section{Related Work}
\label{sec:related-work}

\textbf{Contamination evidence.} Sainz~\emph{et al.}~\cite{sainz2023contamination} argue that per-benchmark contamination measurement should be standard practice rather than an afterthought, and Balloccu~\emph{et al.}~\cite{balloccu2024leakcheat} substantiate the concern empirically, tracing leaked benchmark references into closed-source model cards. Dong~\emph{et al.}~\cite{dong2026generalization} extend this line specifically to code generation, distinguishing genuine generalisation from memorisation in code-LLM evaluation. These studies establish that contamination is real and detectable after training has already happened; they do not, by themselves, offer an evaluation protocol that prevents it at measurement time, which is the gap the present work addresses for test generation specifically.

\textbf{Dynamic evaluation.} A growing line of work responds to static-benchmark contamination by generating evaluation instances at test time rather than drawing from a fixed set. DyVal~\cite{zhu2024dyval} constructs reasoning problems from dynamic graphs; LiveBench~\cite{white2025livebench} refreshes its problem pool on a rolling schedule against continuously updated sources; BeyondBench~\cite{srivastava2026beyondbench} generates algorithmic problems with mathematical correctness guarantees; MATHEMAGIC~\cite{obrien2025mathemagic} applies the same generative principle to mathematics benchmarks; and LLM-as-an-Interviewer~\cite{kim2025interviewer} replaces static test sets with an adaptive, dialogue-driven evaluation. Each demonstrates that generative evaluation is practical at scale and resists the specific contamination failure mode static benchmarks exhibit. None targets unit-test generation, where the object being evaluated is itself executable code accompanied by a correctness oracle -- a structurally different scoring problem from question-answering or mathematics, since a generated test can be assessed by execution rather than by comparison to a reference string.

\textbf{Dynamic and contamination-aware benchmarking for code.} Closer to the present setting, DyCodeEval~\cite{chen2025dycodeeval} and the benchmark-usefulness study of Guan~\emph{et al.}~\cite{guan2025benchmarkuseful} both apply dynamic regeneration to code-reasoning benchmarks, and Code2Bench~\cite{zhang2025code2bench} scales dynamic benchmark construction directly from source repositories. TestEval~\cite{wang2024testeval} and the software-evolution study of Haroon~\emph{et al.}~\cite{haroon2026evolution} evaluate LLM test generation specifically, the latter tracking test quality as the codebase under test changes over time; MuCoCo~\cite{chou2026mucoco} evaluates code-LLM consistency via automated mutation-style perturbation, a close methodological parallel to the mutation-testing scoring used here. The static comparator adopted in this work, UnLeakedTestBench (ULT)~\cite{huang2026ult}, is itself a response to contamination: its authors decontaminate a corpus of real-world functions and construct PLT, a deliberately leaked twin, so that any contamination-consistent score gap between the two becomes directly observable -- an experimental design this work reuses as one of its own contamination-evidence comparisons. Codex/HumanEval~\cite{chen2021codex} established code-generation benchmarking as a discipline but is widely reported as contaminated in later models, illustrating the long-run failure mode a purely static release cannot avoid; BigCodeBench~\cite{zhuo2025bigcodebench} serves in this work as an external, independently maintained code-generation proxy against which the dynamic benchmark's construct validity is checked (Section~\ref{sec:methods}).

\textbf{The gap.} No prior dynamic-benchmarking study combines template-based, seeded regeneration with a mutation-testing oracle for unit-test generation specifically, and none pairs an observational contamination comparison (dynamic versus a decontaminated static benchmark and its leaked twin) with a causal one (direct fine-tuning on the static benchmark's own ground truth, isolating contamination-driven inflation from generic capability gain). This work supplies both, together with a construct-validity check against an external, non-test-generation proxy, to establish not only that the dynamic benchmark resists contamination but that it continues to measure a capability recognisable to an independent evaluation.
