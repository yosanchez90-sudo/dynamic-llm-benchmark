\section{Literature review}
\label{sec:related-work}

\textbf{Contamination evidence.} LLMs reproduce training sequences at rates that grow with model scale and duplication~\cite{carlini2023quantifying}; Dong~\emph{et al.}~\cite{dong2026generalization} extend this to code generation. These studies establish contamination is real and detectable after training happens.

\textbf{Dynamic evaluation.} To respond to static-benchmark contamination, evaluation instances are generated at test time. DyVal~\cite{zhu2024dyval} constructs reasoning problems from dynamic graphs (general reasoning, not code; no execution oracle); LiveBench~\cite{white2025livebench} refreshes monthly (a fixed release still sits between refreshes, and each new source is exposed once drawn from the public web); BeyondBench~\cite{srivastava2026beyondbench} generates algorithmic problems with correctness guarantees (puzzle-style, not free-form code grounded in real functions); LLM-as-an-Interviewer~\cite{kim2025interviewer} replaces static sets with dialogue-driven evaluation (at the cost of a second LLM's own judgement and bias). Each resists the contamination failure mode static benchmarks exhibit; none targets unit-test generation, where a generated test is assessed by execution rather than comparison to a reference string.

\textbf{Dynamic and contamination-aware benchmarking for code.} Closer to the present landscape, DyCodeEval~\cite{chen2025dycodeeval} applies dynamic regeneration to code-reasoning tasks such as output prediction, not test generation; Code2Bench~\cite{zhang2025code2bench} scales dynamic construction from source repositories, but by mining them at construction time remains exposed to the same web-scraping leak pathway it avoids; LiveCodeBench~\cite{jain2025livecodebench} draws problems from contests held after training cutoffs, a moving cutoff that dates quickly and is not itself test generation.

Automated unit-test generation predates LLMs: EvoSuite~\cite{fraser2011evosuite} synthesises suites by evolutionary search, and recent studies evaluate LLMs on the task directly~\cite{schafer2024empirical}. TestEval~\cite{wang2024testeval} and Haroon~\emph{et al.}~\cite{haroon2026evolution} evaluate LLM test generation, the latter tracking quality as the codebase evolves; MuCoCo~\cite{chou2026mucoco} evaluates code-LLM consistency via mutation-style perturbation, a closely aligned methodology here. The static comparator adopted in this work, UnLeakedTestBench (ULT)~\cite{huang2026ult}, decontaminates real-world functions and constructs PLT, a deliberately leaked twin, so any contamination-consistent score gap becomes observable, a design this work reuses. BigCodeBench~\cite{zhuo2025bigcodebench} serves here as an external code-generation proxy for construct validity.

\textbf{The gap this work addresses for test generation.} No prior dynamic-benchmarking study combines template-based, seeded regeneration with a mutation-testing oracle for unit-test generation specifically, and none pairs an observational contamination comparison (DyMuT vs ULT/PLT) with a causal one (direct fine-tuning on ULT's own ground truth, isolating contamination-driven inflation from generic capability gain). This work supplies both, together with a construct-validity check against an external, non-test-generation proxy, to establish not only that DyMuT resists contamination but that it continues to measure a capability that an independent evaluation recognises.
