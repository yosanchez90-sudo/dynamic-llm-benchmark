\section{Introduction}
\label{sec:introduction}

Static benchmarks for evaluating large language models (LLMs) become contaminated through ordinary use~\cite{sainz2023contamination, balloccu2024leakcheat}. Once a benchmark is published, its contents leak into future training corpora. This happens directly, when the published set is scraped from the web, and indirectly, when problems sent to commercial model APIs during evaluation are kept and reused for training. When a model has seen a benchmark's problems, or modified versions of them, during training, its reported score measures recall, not the capability the benchmark was built to test. Sainz~\emph{et al.}~\cite{sainz2023contamination} argue that contamination should be measured for every benchmark; Balloccu~\emph{et al.}~\cite{balloccu2024leakcheat} quantify the leak empirically, finding that roughly 42\% of 255 reviewed evaluation papers leaked data to closed-source models, some 4.7 million samples across 263 benchmarks. Static benchmarks are vulnerable to this. Once published, their exact content is a fixed target that later training runs absorb. % cite:external -- "42" and "4.7" are Balloccu et al.'s own reported figures, verified directly against the source paper, not this project's computed values

Test generation for software is a specific instance of this general problem. An LLM asked to write unit tests for a function can look highly capable if it memorised that function's reference tests during training. The same model may fail on a function it has not seen. UnLeakedTestBench (ULT)~\cite{huang2026ult} is the closest static baseline. Its authors decontaminate a set of real-world functions and pair each with a deliberately leaked twin, PLT, so that any contamination signal becomes visible. That design makes ULT and PLT the best static comparator here. But a decontaminated benchmark, once published, faces the same risk it was built to avoid. Nothing stops its content entering a future model's training data. A benchmark that generates fresh problem instances at evaluation time, from a private template grammar, avoids this. No static benchmark can, however carefully it is decontaminated.

This dissertation builds such a benchmark and tests that claim. DyMuT is built from sixty parameterised templates spanning four cyclomatic-complexity (CC) tiers. Each template produces distinct, seeded problem instances, scored against a reference oracle by a mutation-testing suite instead of a fixed set of expected outputs. The aim is to establish whether this design resists the score inflation that contamination causes in static benchmarks, while still separating strong test generation from weak.

Three objectives follow from this aim. The first is observational. Compare mutation-testing performance across nine models on DyMuT, on ULT, and on ULT's leaked twin PLT, and check whether either static benchmark shows the pattern contamination would produce: higher scores on the leaked variant. The second is causal. Fine-tune a small open-source model on ULT's ground truth, then measure whether the gain carries over to DyMuT or stays on the static benchmark. This distinguishes inflation caused by contamination from any real capability the fine-tuning adds. The third checks construct validity. Does DyMuT's ranking of models agree with an external, independently maintained measure of code-generation ability? A benchmark that resists contamination but measures nothing recognisable would not be a useful replacement.

These objectives map onto five research questions. RQ1 asks whether DyMuT resists the contamination a static benchmark absorbs; RQ2 asks how mutation-killing effectiveness changes with complexity tier; RQ3 asks whether any static-dynamic score gap is larger at low tiers than high ones; RQ4 asks whether DyMuT's model rankings are stable across independent re-instantiations; RQ5 asks whether DyMuT's ranking agrees with an external, independently maintained code-generation proxy. Six hypotheses test these questions. Table~\ref{tab:hypotheses} lists each research question, the hypothesis that tests it, the prediction made, and the verdict reached.

This work makes four contributions. It builds DyMuT, a template-based, mutation-scored benchmark whose problem space is a private grammar rather than a fixed instance set, so no generated instantiation is itself a publishable, memorisable artefact. It pairs an observational contamination comparison (nine models against a decontaminated static benchmark and its deliberately leaked twin) with a causal one (direct fine-tuning on that static benchmark's own ground truth), isolating contamination-driven inflation from ordinary capability gain in a way an observational comparison alone cannot. It checks construct validity against an external, non-test-generation proxy, so contamination resistance is reported alongside evidence that the benchmark still measures something an independent instrument recognises. It also reports, as a by-product of preparing ULT for fine-tuning, a reproducibility finding on that benchmark's own published scoring code (Section~\ref{sec:results-h3}).

The scope is deliberately bounded. Every problem is a single Python function; no multi-file or multi-function task is considered. Mutation testing here uses seven semantic-altering-change operators only, chosen because they can change a program's observable behaviour; semantic-preserving-change operators are out of scope for this study (Section~\ref{sec:conclusion}). Every reported result uses one sampled attempt per problem ($K=1$), not a best-of-$k$ or majority-vote setting. Nine models are evaluated; the causal fine-tuning result uses one model, at the smallest of three open-source scales considered, and one fine-tuning method, LoRA (Section~\ref{sec:methods-finetune}), so no claim in this paper generalises that result to a larger model or to full fine-tuning. Finally, Section~\ref{sec:conclusion} draws conclusions and outlines directions for future work.
