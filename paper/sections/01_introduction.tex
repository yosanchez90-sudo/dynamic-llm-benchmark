\section{Introduction}
\label{sec:introduction}

Static benchmarks for evaluating large language models (LLMs) become contaminated through ordinary use~\cite{sainz2023contamination, balloccu2024leakcheat}. Once a benchmark is published, its contents leak into future training corpora: directly, when the published set is scraped from the web, and indirectly, when problems sent to commercial model APIs during evaluation are retained and reused as training signal. When a model has seen a benchmark's problems, or modified versions of them, during training, its reported score reflects recall rather than the capability the benchmark was designed to measure. Sainz~\emph{et al.}~\cite{sainz2023contamination} argue that contamination should be measured for every benchmark rather than assumed away; Balloccu~\emph{et al.}~\cite{balloccu2024leakcheat} quantify the leak empirically, finding that roughly 42\% of 255 reviewed evaluation papers leaked benchmark data to closed-source models, some 4.7 million samples across 263 benchmarks. Static benchmarks are structurally vulnerable to this failure mode: once published, their exact content is a fixed target that later training runs can absorb, whether deliberately or as an artefact of indiscriminate web crawling. % cite:external -- "42" and "4.7" are Balloccu et al.'s own reported figures, verified directly against the source paper, not this project's computed values

Test generation for software is a specific instance of this general problem, and an under-examined one. An LLM asked to generate unit tests for a function can appear highly effective at a task if it has memorised the function's own reference tests during training, even though it cannot do the same for a function it has not seen. The most directly relevant static baseline available for this problem, UnLeakedTestBench (ULT)~\cite{huang2026ult}, addresses this by construction: its authors decontaminate a set of real-world functions and pair each with a deliberately leaked twin (PLT) to make the contamination signal directly observable. This makes ULT/PLT the natural static comparator for the present work, but a decontaminated benchmark, once published, is itself subject to the same absorption risk that motivated its own construction: nothing prevents its content from entering a future model's training data. A benchmark whose problem instances are freshly generated at evaluation time, from a private template grammar rather than a fixed published set, is structurally resistant to this failure mode in a way no static benchmark, however carefully decontaminated at the time of release, can remain over time.

This dissertation evaluates that claim directly. A dynamic, template-based benchmark for LLM unit-test generation is constructed from sixty parameterised templates spanning four cyclomatic-complexity (CC) tiers, each template capable of producing many distinct, seeded problem instances scored against a reference oracle by a mutation-testing suite rather than a fixed set of expected outputs. The aim is to establish whether this generative, oracle-by-construction design measurably resists the contamination-induced score inflation that affects static benchmarks, without sacrificing the ability to discriminate genuine test-generation capability across models of different scale and provider.

Three objectives follow from this aim. The first is observational: compare mutation-testing performance across nine models from four providers on the dynamic benchmark against their performance on ULT, and separately against ULT's leaked twin PLT, to establish whether either static reading shows the contamination-consistent pattern (higher scores on the leaked variant) that the dynamic benchmark should not. The second is causal: fine-tune a small open-source model directly on ULT's own ground truth and measure whether its gain transfers to the dynamic benchmark or remains confined to the static one it was trained on, which isolates contamination-driven inflation from any generic capability improvement the fine-tuning step also produces. The third is a construct-validity check: establish whether the dynamic benchmark's ranking of models agrees with an independent, externally validated proxy of code-generation capability, since a benchmark that resists contamination but no longer measures anything recognisable would not be a useful substitute for the static benchmarks it is intended to replace.

These objectives map onto five research questions (RQ1--RQ5), tested by six pre-registered hypotheses (H1--H6, H1 carrying two tests) evaluated in Section~\ref{sec:results}: RQ1 asks how much the dynamic benchmark reduces contamination-induced inflation relative to ULT, addressed observationally by H1 and causally by H2; RQ2 asks how test-generation effectiveness varies across the four CC tiers, addressed by H3; RQ3 asks whether contamination-induced overestimation is larger at lower complexity tiers, addressed by H4; RQ4 asks whether model rankings are stable across independent re-instantiations of the dynamic benchmark, addressed by H5; and RQ5 asks how well the dynamic benchmark's ranking agrees with an external code-generation proxy relative to the static benchmark's own agreement, addressed by H6.
