# Figure audit — provenance, three new thesis figures, and classification

## 0. Provenance status of every figure

**Mechanism**: `analysis/figures/` is entirely gitignored (`.gitignore:49`), so
no image file itself is ever committed. This project's convention (already
established by `plot_comparison_c_onset_curve.py`, `plot_rq5_correlation.py`,
and `plot_rq5_cross_family_correlation.py` before this audit) is to write a
provenance sidecar — `stamp_block()`'s git-hash + timestamp, sources, output
path — to `analysis/<figure-stem>_PROVENANCE.md` instead, which is **not**
gitignored (only `.csv`/`.xlsx` are excluded from `analysis/` root). The
image is regenerable from source data at any time; the sidecar is the
committed proof that a given regeneration happened, from what, and when.

## 1-2. Three new thesis figures

All three registered in `scripts/build_thesis_assets.py` (steps
`ranking_matrix_heatmap_figure`, `noise_floor_figure`,
`collapse_vs_survival_figure`), each reads only from already-computed CSVs
(`analysis/ranking_matrix_correlations.csv`,
`analysis/rq5_cross_family_correlations.csv` /
`rq5_cross_family_model_ranking.csv`) or recomputes directly from
`data/results/dynamic/*.jsonl` via the existing, tested
`src/Analysis/stability.py` machinery — no new model runs, no new metric
definitions.

**(a) `ranking_matrix_heatmap.pdf`** — 4 metrics × 3 benchmark pairs,
Kendall τ colour-scaled on a diverging map centred at 0 (τ is genuinely
bipolar — sequential-hue-for-magnitude would be the wrong tool here, per
the dataviz skill's diverging-data rule). `**` marks Holm-survived
significance, `*` marks raw-only significance — encoded in the cell text,
not colour alone, so significance status doesn't depend on a reader's
colour perception. n annotated per cell. Two panels (canonical-9,
canonical+cross-family-13), same colour scale, corrected as two
**separate** 12-test Holm families (not one pooled 24-test family) — same
discipline as RQ4/H5's N=4-vs-all-pairs split.

**(b) `noise_floor.pdf`** — between-model spread / mean within-model SD,
grouped bars by metric within each of Dynamic L1-L4 + pooled. The specific
4-model unresolvable cluster (Claude Haiku > Claude Sonnet > Qwen 32B >
Gemini Flash-Lite, `analysis/RQ5_DIAGNOSTICS.md`) is annotated by name on
conditional Mut@K's pooled bar — a named citation of that specific
pooled-conditional-Mut@K finding, not re-derived generically for every
cell in this figure. Raw table: `analysis/noise_floor_by_tier.csv`.
**Noted, not previously documented**: conditional Mut@K's resolving power
is not monotonic across tiers — it dips sharply at L3 (ratio 3.7, vs 14.6
at L2 and 19.9 at L4), driven by an unusually high between-model SD at L3
(0.066 vs 0.009-0.018 elsewhere) — worth a specific mention if this figure
is discussed in the text, not just read off visually.

**(c) `collapse_vs_survival.pdf`** — 2×2 panels (raw Mut@K / coverage-
adjusted × canonical-only-n_models=3 / canonical+cross-family-n_models=7), Dynamic↔
BigCodeBench (Complete-split). **Correction to the prompt that requested
this figure**: the "minimum achievable p" at n_models=3 is **not** 0.167 —
verified directly against this project's own permutation test
(`src/Analysis/correlation.py::_permutation_p`, which is two-sided,
`abs(stat) >= abs(observed)`), where only 2 of the 3!=6 possible
permutations of a 3-element vector (the identity and the full reversal)
can match a perfect observed correlation, giving a floor of 2/6 ≈ **0.333**
— matching every n_models=3 permutation p-value already recorded elsewhere in
this project (e.g. `analysis/RQ5_PROVENANCE.md`'s 0.331-0.341 figures).
0.167 (1/6) would be the floor for a one-sided test only, which this
project's own statistical convention does not use. The figure and its
provenance both state 0.333, not 0.167, for this reason. Thin cells
(`n_defined<20`, e.g. Mistral-7B) are ringed in red, consistent across
this and the heatmap/noise-floor figures.

**Visual grammar applied consistently across all three** (and matched to
the existing `comparison_c_onset_curve.py` conventions): `matplotlib.use("Agg")`
backend, `grid(linestyle="--", alpha=0.4)`, `savefig` to both `.pdf` and
`.png` at `dpi=150, bbox_inches="tight"`, the same provenance-stamping
pattern, and the existing provider/family colour dict (Qwen `#2ca02c`,
gpt `#d62728`, claude `#1f77b4`, gemini `#9467bd`, DeepSeek `#ff7f0e`,
CodeLlama `#8c564b`, StarCoder2 `#17becf`, Mistral `#e377c2`) reused
verbatim in `collapse_vs_survival.py` rather than re-invented. Metric
names on every axis/legend match `analysis/RANKING_MATRIX.md`'s labels
exactly (`exec_rate`, `baseline_pass_rate`, "conditional Mut@K",
"coverage-adjusted Mut@K") — no figure invents its own metric naming.
Thin-cell and Holm-vs-raw-significance markers are the two "identity
never colour-alone" encodings this audit introduces; both are now used in
more than one figure, so they read as a shared convention rather than a
one-off choice.

### Redundancy flagged explicitly, per instruction

`collapse_vs_survival.pdf`'s Dynamic↔BigCodeBench panels (both scopes,
both metrics) cover materially the same ground as 4 of
`rq5_cross_family_correlation.pdf`'s 8 panels. This is a **deliberate**
redundancy, not an oversight: the new figure isolates just this one
argument (with the corrected n_models=3-uninformativeness annotation the older
figure doesn't have), while the older figure keeps the fuller
Dynamic↔ULT comparison the new one doesn't cover at all. Recommendation
above is to lead with the focused figure in the main text and keep the
fuller one as an appendix cross-reference, not to delete either.
