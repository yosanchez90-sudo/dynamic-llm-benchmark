## StableMut@K — is each model's OWN score stable across instantiations?

**Every model's own aggregate mutation score is highly stable across re-instantiations**
— SDs are tight (0.003-0.007) for six of seven canonical models with 2+
instantiations. The one exception, Qwen 1.5B (SD ~0.04), is an order of magnitude
noisier than the rest; worth a specific note in the write-up as a capability-related
finding, not a benchmark-stability problem (see tier breakdown below).

**Verified 2026-07-26 (Part-1 follow-up C): Qwen 1.5B's zero-scorable-L4 pattern is
a genuine capability limitation, not an extraction or scoring bug.** Inspected 3 raw
L4 completions from `Qwen__Qwen2.5-Coder-1.5B-Instruct__dynamic__zero_shot__inst1__20260609T221336.jsonl`
(`L4-aggregate-001`, seeds 1101/1102/1103) end to end — `extracted_test_file` matches
the raw `response` verbatim in every case (extraction did its job), and the failures
split into two distinct, genuine model failure modes:
- **Seeds 1101/1102** (`exec_rate=0.0`, "exec gate failed (collection error)"): the
  model's own generation degenerates into a runaway, near-duplicate
  `@pytest.mark.parametrize` list (e.g. `10, 10, 10, ...` repeated dozens of times,
  growing until the response is cut off mid-list) — a repetition-collapse failure
  mode under L4 complexity, producing syntactically invalid/truncated Python that
  can't even be collected.
- **Seed 1103** (`exec_rate=1.0`, `baseline_passed=False`, "suite failed on
  original"): a syntactically clean, well-formed parametrized test — that asserts
  wrong expected values for `orchestrate`'s actual behavior. The model can write a
  valid test but reasons incorrectly about a complex function's real output.

Both are RQ2-relevant tier-effect findings (a 1.5B model's reasoning and generation
reliability breaking down at CC>=8), not artifacts of this project's own pipeline.

### Why score-level stability (0.82-0.97) reads higher than rank-level tau (~0.6-0.7)

The gap is a genuine rank-vs-score effect, not a data problem — earlier interim reads of tau (0.84 on
~61/180 cells, then 0.593 on ~104/180 cells — see `PROJECT_BRIEF.md` §11) swung much
more than the StableMut@K point estimates did, because **many models cluster closely
in absolute score** (0.82-0.97 for most model variants). Tau is a rank
statistic — it's sensitive to small, noisy score differences flipping the relative
order of two closely-scored models, even when neither model's own score moved much.
This is why the by-model StableMut@K table is the more robust stability claim, and the
Kendall tau table should be reported with its per-pair n and p-values visible, not as
a single blended number — a reader should be able to see that the weaker pairs are
exactly the ones with the fewest models and are not individually significant, rather
than have that folded into one mean.
